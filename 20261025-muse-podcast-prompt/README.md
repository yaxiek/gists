# MuseでPodcastを円滑に作るための共有プロンプト

Muse に貼るだけで、Podcast シリーズの立ち上げから継続制作までを任せられるプロンプトです。
音声生成を一発勝負にせず、調査、品質チェック、改善、評価の記録までを最初から手順に入れています。

## 使い方

1. [prompt.txt](prompt.txt) を開き、右上のコピーボタン（Copy raw file）で全文をコピーします。
2. そのまま Muse に貼ります。書き換える箇所はありません。
3. Muse から3〜5問ずつ質問が来るので答えます。決めていない項目は「おまかせ」で大丈夫です。
4. Muse がシリーズ設計を要約して見せてくれます。問題なければ「これで始めて」と返すと、パイロット版の制作が始まります。

## このプロンプトで Muse がやること

- **最初に確認の往復をする**: テーマ、リスナー、長さ、声、情報源、公開範囲などを聞いてから作り始めます。いきなり作りません。
- **調査メモを先に作る**: 出典URL、使わなかった情報とその理由、中心の問いを残してから台本を書きます。
- **崩れにくい台本を書く**: 冒頭で用語を並べない、列挙を避ける、短い文で区切るなど、音声合成が崩れにくい書き方をします。
- **4段階で品質チェックする**: 無音、音声認識による台本との照合、セグメント間の空白、全セグメントの目視確認。全部合格した音声だけが届きます。
- **不合格なら改善ループを回す**: 壊れた発話だけを特定して直し、原因の推論と一緒にログに残します。上限回数で合格しなければ、正直に報告します。
- **評価を次に活かす**: タップ式の評価や文章の感想を記録し、次回以降の長さ、深さ、話し方に反映します。
- **取り消しにくい操作は確認してから**: 公開RSSや定期配信は、あなたが明示したときだけ設定します。

## Muse が作るファイルの例

```text
podcasts/
├── research/YYYYMMDD-<topic>.md      調査メモ
├── episodes/YYYYMMDD-<name>.mp3      音声
├── episodes/YYYYMMDD-<name>.md       台本・整理メモ（音声と1対1）
├── glossary.md                       用語・読み方セット
├── improvement-log.md                改善ループの記録
└── DB.md / db.json                   内部DB（SQLite）からの書き出し
```

保存先は例です。Muse の環境に合わせて変わることがあります。

## 調整したいとき

prompt.txt の該当箇所を書き換えてから貼ってください。

- 品質チェックの基準: 全体の一致度 0.72以上、冒頭45秒の一致度 0.55以上、セグメント間の空白 3.5秒未満、無音 2秒未満
- 改善ループの最大試行回数: 5回

ほかの希望（声、長さ、扱わない話題など）は、書き換えなくても最初の質問で伝えれば反映されます。

## コツ

- 最初は「まず1本だけ」で試し、声・深さ・話し方を確認してから定期配信に広げると失敗が減ります。
- うまくいった改善は、その場限りで終わらせず、用語集や制作フローに追記してもらいましょう。
- 音声が崩れる回はあります。大事なのは、崩れた音声を届けず、検査と記録で次に活かすことです。
- 音声が不自然だと感じたら、まず時刻つき書き起こしで確かめてもらってください。
