# MuseでPodcastを円滑に作るための共有プロンプト

[Muse](https://muse.ai/)（Meta のパーソナル AI エージェント）には、最初から Podcast を作る機能があります。頼めば台本を書き、ホストの声で音声まで作ってくれます。

このプロンプトは、その機能を「1本作って終わり」ではなく、シリーズとして継続的に、崩れずに回すための進め方を Muse に渡すものです。音声生成を一発勝負にせず、調査、品質チェック、作り直し、評価の記録までを最初から手順に入れています。

これは個人が作った非公式のプロンプトで、Meta や Muse の公式のものではありません。

## 使い方

1. [prompt.txt](prompt.txt) を開き、右上のコピーボタン（Copy raw file）で全文をコピーします。
2. そのまま Muse に貼ります。書き換える箇所はありません。
3. Muse から3つだけ質問が来ます（テーマ、誰がどんな場面で聞くか、形式と長さ）。選択肢をタップするか番号で答えます。決めていなければ「おまかせ」で大丈夫です。
4. Muse が「決めたこと」と「既定で進めること」をまとめて見せてくれます。変えたいところだけ伝えて、「これで始めて」と返すと、パイロット版の制作が始まります。
5. 完成すると音声が届きます。タップで評価すると、次の回に反映されます。

## 既定で進めること

最初の確認で、Muse が次の既定値を示します。変えたいところだけ伝えれば変えられます。あとから伝えても反映されます。

- **言語**: Muse とのやりとりと同じ言語
- **配信**: まず1本だけ。定期配信は、パイロット版を聞いたあとに Muse から提案されます。
- **公開範囲**: 非公開で自分に届くだけ。公開RSSは、自分から頼んだときだけ設定されます。
- **情報源**: 公式情報、論文、信頼できる報道を優先
- **扱わないもの**: 特定の立場への誘導、私生活の詳細
- **評価**: 配信のたびにタップ式で聞かれます
- **不合格のとき**: 1回の制作で最大5回まで試します（最初の生成を含む）。それでも合格しなければ、「時間を置いて今日中にやり直す / 構成を大きく変えてすぐやり直す / 今回は見送る」から選ぶよう聞かれます。
- **手順の改善**: 制作のたびに学びを小さく反映し、変えた点を1〜2行で報告します。

## このプロンプトで Muse がやること

- **質問は最小限にする**: 結果を大きく左右する3つだけを聞き、ほかは既定値を示して進めます。判断が必要なこと（作り直すか、定期配信にするか）は、必要になったときに聞きます。
- **環境を自分で確かめる**: 使える声や、品質チェックに使う音声認識などの道具が揃っているかを確かめます。問題がなければ報告は一言だけです。
- **調査メモを先に作る**: 出典URL、使わなかった情報とその理由、中心の問いを残してから台本を書きます。
- **崩れにくい台本を書く**: 冒頭で用語を並べない、列挙を避ける、短い文で区切るなど、音声合成が崩れにくい書き方をします。
- **4段階で品質チェックする**: 無音、音声認識による台本との照合、セグメント間の空白、全セグメントを1つずつ読んでの判定。全部合格した音声だけが届きます。音声認識の聞き違いを欠陥と取り違えないための条件も入っています。
- **壊れたところだけを段階的に直す**: 言い換え → 話者の入れ替え → 語の差し替え → 一節の組み替え、と段階を上げて直し、原因の推論と一緒にログに残します。
- **連絡は必要なときだけ**: 完成したときと判断が必要なときだけ連絡します。検査の数値や細かい記録は、聞けば見せてくれます。
- **評価と学びを次に活かす**: 評価や感想を記録し、次回以降の長さ、深さ、話し方に反映します。制作の手順そのものも、学びに合わせて少しずつ直します。

## 期待値の目安

1回目の生成で全部の検査に合格することは、ほとんどありません。作者の環境では5本すべてを配信まで持っていけましたが、1回目で合格した回はなく、1本あたり平均7回ほど試行しました。1試行は生成と検査で5〜10分ほどかかり、1本に1時間ほどかかることもあります。

不合格が続いても、それは検査が働いている証拠です。崩れた音声が届かないことを優先しています。

試行と検査を重ねる分、Muse の利用枠（Muse トークン）も多めに使います。無料枠で試す場合は、まず1本だけで様子を見てください。

## 品質チェックの基準を変えたいとき

基準は prompt.txt に書いてあります。変えたいときは、該当箇所を書き換えてから貼ってください。

- 全体の一致度 0.72以上、冒頭の一致度 0.55以上、セグメント間の空白 3.5秒未満、無音 2秒未満
- 一致度の基準は、少数の実測から置いた経験値です。計算方法を変えるときは、基準も合わせて見直してください。

## Muse が作るファイルの例

```text
podcasts/
├── research/YYYYMMDD-<topic>.md      調査メモ
├── episodes/YYYYMMDD-<name>.mp3      音声
├── episodes/YYYYMMDD-<name>.md       台本・整理メモ（音声と1対1）
├── glossary.md                       用語・読み方セット
├── improvement-log.md                改善ループの記録
└── DB.md / db.json                   内部DB（SQLite）からの書き出し
```

保存先は例です。Muse の環境に合わせて変わることがあります。Muse はユーザーごとに専用のクラウド上のコンピューター（ブラウザーとターミナル付き）を持っていて、品質チェックに使う道具も Muse が自分で用意して動かします。

## コツ

- 最初は1本だけ試し、声・深さ・話し方を確かめてから定期配信に広げると失敗が減ります。
- 音声が崩れる回はあります。大事なのは、崩れた音声を届けず、検査と記録で次に活かすことです。
- 音声が不自然だと感じたら、そう伝えてください。Muse が時刻つき書き起こしで確かめて、直した音声に差し替えます。
